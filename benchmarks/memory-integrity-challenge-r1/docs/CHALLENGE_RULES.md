# Participant rules and safety boundary

1. Compare tools against the same exact `data/events.jsonl`, `data/tasks.jsonl`, and scorer version.
2. Submit one `case_id`, `decision`, `value`, and `evidence_ids` object per JSONL line.
3. Submit method, model/tool version, human intervention, prompts (excluding secrets), and reproducibility commands with any shared result.
4. No real identity, biometric, medical, financial, student, customer, personal memory, key, credential, host identifier, production ledger, or private USB material may be submitted.
5. There is no automatic owner-authority delegation. Testing must not install or execute production memory-writer code. All examples are fictional.
6. Identify disagreement with the rubric rather than changing gold answers silently. Propose changes as a new version with an explanation and regression tests.
7. Keep repository security disclosures private when they involve exploitable findings.
8. The challenge does not solicit unsolicited outreach, DMs, bulk posting, or contact information. Public discussion should be relevant and permission-respecting.
